# Review Gate（审查闸门与审查回路止损）

本文件成文**审查流程**规则。来源 = PR #57（ticket #54）五轮审查暴露的回路缺陷，成文票 = issue #60。

**共同前提 —— 审查对象分两层：**

- **决策层**：决议本身站不站得住。有客观真值，可收敛。
- **元信息层**：描述 / 评论里的计数、措辞、指代、时序、行号、先例断言。**开放文本，改一处会漂移另一处，没有自然终点。**

PR #57 的回路由此产生：修复动作把「修复轮记录」写进描述 ⇒ 新节自带新的可证伪断言 ⇒ 下一轮在新文本上找到新的不精确处。下面四条都建立在「元信息层不拦门」这一判据上。

## 1. 闸门分层：非决策层意见不得拦合并

`review/changes-requested`（label description：「审查不通过」）**只用于下表的「拦」档**。

| 档 | 判据 | 处置 |
| --- | --- | --- |
| **拦** | `Blocking` / `Major`；或 `Minor` 但**导致读者对决议内容做出错误决定** | 置 `review/changes-requested`，修完复审 |
| **不拦** | 纯计数 / 措辞 / 指代 / 时序类 `Minor` / `Nit`，且不影响读者对决议内容的理解 | 发 comment；**不阻塞合并**；作者可择机处理或转票 |

「导致读者做出错误决定」的自查问句（唯一判据，留给审查者判断）：

> **删掉这处错误，读者会不会做出不同的决定？**

会 ⇒ 拦；不会 ⇒ 不拦。**不提供机械判定表** —— 枚举误读场景的成本高于收益。

**不要做**：不取消 `Minor` / `Nit` 等级。**等级照报，只是不再拦门**；发现照旧写全，判据只决定它拦不拦。

**「不拦」档的意见不要求作者逐条回复** —— 强制回复会让该档重新产生一轮往返。

## 2. 修复轮记录不进 PR 描述

修复轮记录**发 PR 评论**（逐轮一条）。核销对象是「本轮意见」，评论天然带时间线；独立文件会进 repo 历史并需清理，故不采用。

PR 描述只保留三块：

1. **决议本体**；
2. **当前验证** —— 最后一次 CI 结论 + 本地实测结论（纯 `docs/**` 改动会命中 CI `paths-ignore`，此时须显式声明证据来源为本地）；
3. **遗留** —— 未处置项 + 归属 / 待裁定人。

**边界**：只约束**此后新建**的 PR。**不回改已合并或已 `review/approved` 的 PR。**

## 3. 非决策层意见累计 2 轮即封口

同一 PR 的**非决策层**意见累计 **2 轮**后，其后同类意见一律 **comment-only**，并提示作者转票或归档。

**阈值取 2 而非 3 的依据**：PR #57 从 r3 起仓库侧行内意见已减少，r4 / r5 全部落在元信息层 ⇒ 阈值放 3 等于让回路再多跑一轮。

## 4. 计数断言规则

凡「复跑实测 = N」「全仓 = N 处」「N 命中」类断言，必须**在同一句里**带：

- **绑定的 SHA** —— 该数必须在**所指 SHA 上**跑出来；
- **产生该数的命令**。

**行数**用 `git grep -c`；**出现次数**用 `git grep -o … | wc -l` —— **两者不可混写**。

**若某 commit 改了被 grep 的文本，该 commit 所属的验证表必须重跑该计数。**

**审查方与作者同责**：审查方给的「可复核命令」本身也是可机械证伪的断言，落笔前必须自己跑一遍。
